# Technical Writing Voice and Tone Style Guide

Ensure all codelab documentation matches a professional, encouraging, and clear technical tone.

## 1. Use the Active Voice

Write in the active voice. It is more direct, clear, and engaging.

- **Avoid:** "The server is started by running the start script."
- **Prefer:** "Run the start script to start the server."

## 2. Eliminate Passive Modifiers (The "Just" and "Simply" Rule)

Never use words that downplay the difficulty of a procedure or introduce unnecessary conversational fluff. These words can alienate learners when things do not work immediately.

- **Forbidden Words:** `simply`, `just`, `obviously`, `easy`, `simple`, `basically`.
- **Avoid:** "Simply click the button and the app will compile."
- **Prefer:** "Click the button to compile the application."

## 3. Be Direct and Procedural

Start instructional steps with strong action verbs.

- **Avoid:** "Next, you will want to open the console and type..."
- **Prefer:** "Open the terminal and run..."

## 4. Address the Reader Directly

Use "you" to refer to the developer completing the tutorial, and "we" for the collaborative duo of mascots or team. Keep it conversational but concise.
