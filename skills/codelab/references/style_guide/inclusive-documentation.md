# Inclusive Documentation Style Guide

All tutorials and code structures must use inclusive language to ensure standard access for all developers.

## 1. Avoid Gendered Language

Use gender-neutral terms when addressing groups or writing instructions.

- **Avoid:** "guys", "he/she", "mankind"
- **Prefer:** "everyone", "developers", "people", "humanity"

## 2. Terminology replacements

Avoid historically insensitive terms in both code configurations and tutorial text.

| Avoid | Prefer |
| :--- | :--- |
| `master` (for git branch or main thread) | `main` |
| `slave` (for worker process) | `worker`, `replica`, `secondary` |
| `blacklist` (for disallowed values) | `blocklist`, `deny-list` |
| `whitelist` (for allowed values) | `allowlist`, `safe-list` |
| `dummy` (for placeholder data) | `placeholder`, `sample`, `mock` |
| `sanity check` | `confidence check`, `smoke test`, `quick verification` |

## 3. Clear, Jargon-Free Communication

Do not assume universal familiarity with highly specific localized idioms or slang. Keep sentences accessible to readers whose primary language is not English.
