# 🕸️ DAG Task Graph & Living Blueprint Orchestrator Specification

This document defines the schema, operational state machine, and pure orchestrator protocol for **Modular Orchestration Decks** generated by the `prompt-writer` skill, integrating Google Antigravity's **Teamwork** principles, **Staged Milestone Decomposition**, **Terminal E2E Convergence**, and the **Adversarial Teamwork Quartet** (Builder, Challenger, Forensic Auditor, Critic, Synthesizer, Sentinel).

---

## 1. Directory Structure of a Modular Orchestration Deck

When operating in Heavyweight Mode, `prompt-writer` compiles user requirements into a namespaced Living Blueprint directory under `.gemini/prompts/<SHORT_ID>/`:

```
.gemini/prompts/<SHORT_ID>/
├── blueprint.json                      # Machine-readable Living Blueprint & 4D task space metadata
├── task_graph.json                     # Dynamic DAG of staged milestones, atomic nodes & E2E convergence
├── orchestrator.md                     # Directives for the Pure Manager thread & dialectical arbiter
├── metadata.json                       # Short ID, status, lineage, mutation generations, and execution info
├── prompt.md                           # Compiled entrypoint & interactive execution launchpad
└── tasks/                              # Atomic worker & reviewer prompts (1 per node)
    ├── task_01_spec.md                 # Milestone 1: Specifications & Contracts
    ├── task_02_pool.md                 # Milestone 2: Core Builder implementation
    ├── task_02_challenger.md           # Milestone 2: Hostile fuzzer / stress test directive
    ├── task_02_forensic.md             # Milestone 2: Empirical anti-mock test auditor directive
    ├── task_final_e2e_convergence.md   # Final Milestone: Full system assembly & E2E suite
    └── task_retro_critique.md          # Dialectical gap analysis & evolution trigger
```

## 3. Pure Orchestrator (Manager) Protocol & Milestone Execution

The executing main thread operates under the strict **Pure Orchestrator Protocol**:

1. **Zero Direct Implementation**: The Manager thread NEVER calls code-editing tools directly on target source files.
2. **Milestone Progression & Barrier Synchronization**:
   - The Manager processes nodes Milestone by Milestone.
   - All nodes in Milestone $K$ must reach `VERIFIED` and clear the milestone barrier before nodes in Milestone $K+1$ are dispatched.
3. **Subagent `/Goal` Execution (`invoke_subagent`)**:
   - For each ready node in the active milestone, the Manager launches a specialized worker subagent via `invoke_subagent`.
   - The Manager passes the intent specification (`tasks/<task_file>.md`) as a `/goal` prompt.
4. **Adversarial Stress Testing (Challenger)**:
   - When the Builder signals completion, the Manager immediately dispatches the **Challenger** subagent (`adversarial_challenge`).
   - The Challenger attempts to break the implementation with hostile inputs, race conditions, or edge-case fuzzing.
5. **Dialectical Reconciliation & In-Flight Mutation**:
   - If the Challenger detects a breach, the Manager dispatches a **Synthesizer / Arbiter**.
   - The Synthesizer updates data contracts and injects new remediation child nodes into the active milestone in `task_graph.json` (capped at `MAX_MUTATIONS = 4`).
6. **Forensic Evidence Verification (Forensic Auditor)**:
   - Once the Challenger finds zero exploits, the Manager launches the **Forensic Auditor**.
   - The Auditor verifies that tests executed on physical disk, AST checks prove no mocks bypass business logic, and SHA-256 hashes are stamped into `.gemini/EVIDENCE.md`.
7. **Terminal E2E Convergence Milestone (`task_final_e2e_convergence`)**:
   - When all prior milestones are `VERIFIED`, the Manager enters the terminal **E2E Convergence Milestone**.
   - Assembles all generated modules, runs full cross-service integration suites, validates end-to-end user journeys, and executes `validate_evidence.py`.
8. **Final Sentinel Holistic Gate**:
   - The Sentinel performs final verification to guarantee 100% Plan-to-Artifact parity, zero TODOs, and full system integrity before marking the project `COMPLETED`.
